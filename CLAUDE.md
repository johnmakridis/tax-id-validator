# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run build` — compiles `src/` to `lib/` via `tsc` (runs `prebuild` first, which deletes `lib/` via `shx rm -rf lib`)
- `npm run lint` — runs `tslint -p tsconfig.json`
- `npm run prepare` — runs automatically on install; just calls `build`
- There is no test runner configured. `test.js` is an ad-hoc manual script (`node test.js`) that requires the compiled `lib/index.js`, so run `npm run build` first if it's out of date.

There is no `test` npm script. To exercise a change manually, build then run `node test.js` (edit the `country_code`/`tax_id` values in that file for the case you're checking).

## Architecture

This is a small TypeScript library (published as `@johnmakridis/tax-id-validator`) that validates tax ID / VAT number formats by country using regex, and optionally checks EU VAT numbers live against the VIES web service.

- `src/config.ts` — a single large `countries: Country[]` array covering every ISO country. Most entries have `tax: null` (unsupported). Supported countries have one or more entries in `tax[]`, each with an `enum` id, a `regex` array (currently always exactly one regex), an `example`, and an optional `vat_prefix` (used for EU VAT numbers, e.g. `'DE'`, `'FR'`). Adding support for a new country/tax type means adding/editing an entry here — this is almost always the only file that needs to change for that kind of task.
- `src/models/index.ts` — shared TypeScript interfaces (`Country`, `ValidationResponse`, `VIESRequestBody`, `VIESResponse`).
- `src/index.ts` — the `TaxIdNumberValidator` class, the package's public API:
  - `validate({country_code, tax_id})` — looks up the country, enforces `vat_prefix` if present, tests `tax_id` against the country's regex(es), and returns a `ValidationResponse`. Throws if the country code isn't supported or has no validators.
  - `getAllCountries()` / `getAvailableCountries()` — full list vs. only countries with at least one working regex.
  - `getAvailableCountryNames()` / `getAvailableCountryCodes()`.
  - `getVIESData(params)` — validates format locally first, then SOAP-POSTs to the EU VIES `checkVatService` (via `axios`) and parses the XML response (via `xml2js`) to confirm the VAT number is real and fetch the registered business name/address. Only meaningful for EU countries with a `vat_prefix`.

### Build output

`lib/` is git-ignored source-of-truth-wise but is currently committed in this working tree as compiled output (`main`/`types` in `package.json` point into `lib/`). It is regenerated by `npm run build` — don't hand-edit `.js`/`.d.ts` files under `lib/`, edit the corresponding `src/` file and rebuild.

### Adding/editing a country's validation rules

Each `tax[]` entry in `src/config.ts` needs: `vat_prefix` (string or `null`), `enum` (unique lowercase id, convention `<country-code-lowercase>_<type>`), `tax_id_description`, `tax_id_description_country` (format: `"<Country name> (<tax_id_description>)"`), `example`, and `regex` (array with one `RegExp`). Recent history follows the pattern "minor: added support for `<Country>`" as the commit message for these additions.
